# v0.1.7

## Breaking Changes

- 隐藏 self-loop 命令由 `/.todo` **改名**为 `/.go`。这是重命名而非新增别名：旧的 `/.todo` 不再识别，会返回 `unknown command`。仅管理员可用、不出现在 `/help`，用途不变（把参数作为「修复/改进 bridge 自身」的需求交给 agent 驱动 self-loop）。管理员请改用 `/.go <需求>`。

## Features

- **话题模式：顶层 @bot 立即起独立会话并发跑，不再排队**（rc.7）。Feishu 顶层 @bot 消息 `thread_id=""` 之前会退化与 chat root 同 key，同 chat 所有 @bot 落同一 session 被严格 FIFO。新路由：`IsGroup && Mentioned && ThreadID==""` 时 mint 合成 thread key `@bot:<msg_id>`，每条 @bot 独立 session、独立 batch、并发跑；话题内续问通过 `TopicAliasStore` 别名（rc.8 已持久化）路由回同一 pending session。
- **话题 session 首轮继承主会话上下文**（rc.3）。Topic 会话模式下，话题 session 首次执行会用 Claude 官方 `--fork-session` 从主 session 分叉出一份新 Claude session，让话题 session 首轮就拥有主消息里的全部上下文；之后两个 session 各走各的 AgentSessionID，互不污染。Codex 分支暂不参与（CLI 无 headless fork）。
- **`/config` 表单恢复「推理深度」（effort）下拉，`/local-config` 可逐群覆盖**（rc.6）。四档 `default / low / medium / high`，`default` 显式标注「跟随 Agent 默认」。全局保存有 `isKnownEffort` 校验，非法值触发 `config_save_failed` 审计。`/local-config` 概览多渲染一行「推理深度：<value> （本群）/（继承）」。

## Bug Fixes

- **停止按钮真正停得掉正在跑的 run**（rc.9 首次灰度）。`CLIExecRunner.Run` 起 claude/codex CLI 时未设进程组，点停止只 SIGKILL 直接子进程，真正 streaming 的孙进程（bash 循环 / 工具 / sleep）被 init 收养继续跑、仍持 stdout 写端，导致 `parseClaudeStream.Scan()` 永久阻塞、`cmd.Wait()` 不返回、走不到停止终态。新增 `procgroup_unix.go`：`Setpgid=true` + `cmd.Cancel` 对整组发 SIGTERM + `WaitDelay=5s` 兜底 SIGKILL；非 unix 有空实现保可移植。卡片按钮与 `/stop` 两条停止路径同源受益。
- **引用消息的正文注入 agent prompt**（rc.9 首次灰度）。引用/回复某条消息再 @bot 时，飞书入站事件只带被引用消息的 `parent_id`（不含正文），且该 id 在 `feishu.Event→bridge.Message` 映射时被丢弃，AI 看不到被引用内容。修复：`bridge.Message` 透传 `ParentID`；新增 `MessageFetcher` seam 按 parent_id 回查正文；`session.Input` 加 `QuotedText`/`QuotedSender`；`BuildBatchPrompt` 把「> 引用块」渲染在用户提问前。回查失败降级为 audit `quoted_message_fetch_failed`，单条纯文本无引用保持旧 fast-path 不变。
- **话题模式：同一话题内会话反复切换/丢失上下文**（rc.8）。rc.7 引入的 per-mention 合成 session key `@bot:<msg_id>` 只把真 Feishu `thread_id` 绑在内存，supervisor 重启/升级后绑定全丢，已有话题里的后续消息落到全新空会话。修复：① `TopicAliasStore` 持久化（原子 temp+rename、schema version、revision、有界淘汰、开机加载）；② `root_id` 自愈——`sessionKeyForModeWithAlias` 在别名 miss 时把真 thread 消息路由到 `@bot:<root_id>`（话题 root 即那条 seed 出合成 key 的原始 @bot 消息），别名映射丢失也能续上；③ 附带修掉 `RecordCardReply` 的 bind bug（原来从 `replyToMessageID` 取别名，话题内后续消息的 reply 目标是它自己而非 root，会把别名污染成 `@bot:<follow-up>`）。
- **话题模式：顶层 @bot → 从 bot 回复进入话题 → 话题内首条不 @bot 的消息不再被丢弃**（rc.5）。`intake.go` 的 `mark := msg.Mentioned && msg.ThreadID != ""` 需要 `ThreadID != ""` 才 Mark 话题参与，而顶层 @bot 消息 `ThreadID` 为空，bot 用 `reply_in_thread=true` 回复后飞书分配的 `omt_*` id 从没被 bridge 学习，导致同话题内不 @bot 的下一条消息 `participated=false` 被 skip。新增 `CardKitTopicJoinObserver` 可选接口，CardKit renderer 在 reply 成功且 `replied.ThreadID != ""` 时通过 type assertion 上报参与，bridge 端同步调 `TopicParticipation.Mark` 并写 `topic_participation_auto_joined` 审计。
- **首轮卡片补齐 Session ID 与上下文余量**（rc.4）。`agentCardStream.Handle` 会立刻采纳 stream 事件里带的 agent session id（Claude 的 `system.init.session_id`、Codex 的 `thread.started.thread_id`），`FinishTransformed` 从 `postRunMeta` 返回的 meta / result 兜底回填 SessionID。之前首轮 SessionID 一直是空、导致侧车按空 sessionID 查不到、`ctx: N%` 也一起丢失，现在首轮就能看到 6 位 Session ID 和上下文占用行。
- **元信息行开启后 Codex 第一排缺少模型**（rc.2）。改为读取 Codex context-usage sidecar 已导出的真实模型，并在 runner 协议未上报模型时显示，例如 `⚙️ 019f93 · 🧠 gpt-5.6-sol · 🟢 ctx: 47%`。回填严格限定 Codex；Claude 保持仅使用 runner 返回的实际模型。
- **全局 Agent 切换为 Codex 后，Claude 专属命令误复用 Codex binary/preset**（rc.1）。之前 `/.todo`（现 `/.go`）等 Claude 专属命令在全局切到 Codex 时会把 `--output-format stream-json` 传给 Codex 导致启动失败。显式运行类型现在始终决定对应的 binary 与 home preset，Codex 与 Claude 可以稳定并存和切换。

## Upgrade Notes

- **`/.todo` 已停用**，管理员触发 self-loop 请改用 `/.go <需求>`（唯一破坏性变更）。
