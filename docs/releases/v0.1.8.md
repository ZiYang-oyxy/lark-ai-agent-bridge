# v0.1.8

## Breaking Changes

- 隐藏 self-loop 命令由 `/.todo` **改名**为 `/.go`。旧 `/.todo` 不再识别，返回 `unknown command`。仅管理员可用、不出现在 `/help`，用途不变。

## Features

- **`/config` 元信息行拆成三个独立开关**。原「元信息行」一开就同时打开 agent 行（agent/会话/模型/tokens）与主机行（user/ip/workdir），两行只能整体显隐。现在 `/config` 里新增「📊 元信息行」section，提供三个独立下拉：「Agent 行」「主机信息行」「开发者行」，可各自单开单关；`/local-config` 支持按群独立覆盖每一个开关。旧配置 `show_meta_rows: true` 自动迁移为 agent+runtime 两行同开。
- **新增开发者行**。渲染 `<emoji> v<current> · ⬆️ 最新 v<latest>`，前置 emoji 兼作版本通道指示——开发者模式（rc 通道）`🐛`，正式版通道 `🦋`，一眼能看出"当前跑在哪个版本、哪个通道"。最新版本号走 update client 内存缓存读取（cache-only、无 HTTP 请求），cache 冷时省略"最新"段。
- **`/help` 升级卡展示所有跨版本 release note**。跨多个版本升级时把当前 → 目标之间所有版本的 release note 依次分节打印（newest-first），不再只显示目标版本一份。同 core 的 rc.N→rc.M 区间自动展开；跨 core 或不可解析时降级为仅目标版本。
- **`/config` 与 `/status` 也显示升级提示**（此前只有 `/help` 有）。仅在 `UpdateAvailable=true` 时展示，避免"已是最新"等低价值状态挤占卡片顶部。
- **`/config` 各段默认收起**。🤖 运行参数 / 💬 会话行为 / 👥 群消息 / 📊 元信息行四段用 collapsible panel，展开更主动。
- **/help 升级失败卡附「占用中的会话」清单**。有任务运行或排队时不再只显示一句提示，而是列出 `# / Agent / Chat / 工作目录 / 状态 / 最近活跃` 表格，`state` 分 `running` / `running (queued=N)` / `pending confirm`。
- **群聊 topic 模式下 @bot 立刻起独立会话、并发不排队**。顶层 @bot 消息用 `@bot:<msg_id>` 合成 session key，每条独立 session；话题内后续消息通过持久化 alias（`topic-aliases.json`）+ `root_id` 兜底自愈路由回同一 session，supervisor 重启后不丢续聊上下文。
- **引用消息 @bot 时，被引用消息正文自动进入 agent prompt**。此前飞书事件只带 `parent_id`（无正文），AI 看不到被引用内容；现在按 parent_id 回查正文，渲染成「> 引用块」放在提问前。
- **Supervisor 启动自检 rc 通道配置**。若配了 `LAB_UPDATE_MANIFEST_URL`（stable）却漏配 `LAB_UPDATE_PRERELEASE_MANIFEST_URL`，Bridge 启动时会在 stderr 打一行 `[warn] LAB_UPDATE_PRERELEASE_MANIFEST_URL 未配置...`，避免"发了 rc → 用户 /help 看不到"这类根因反复追查。

## Bug Fixes

- **飞书卡片「停止」按钮真正停得掉正在跑的 run**。此前 `CLIExecRunner.Run` 起 claude/codex CLI 时未设进程组，点停止只 SIGKILL 直接子进程（Node 壳），真正 streaming 的孙进程（bash 循环 / 工具 / sleep）被 init 收养继续跑、仍持 stdout 写端，导致 `parseClaudeStream` 永久阻塞、`cmd.Wait()` 不返回、走不到停止终态。新增 `procgroup_unix.go`：`Setpgid=true` + `cmd.Cancel` 对整组发 SIGTERM + `WaitDelay=5s` 兜底 SIGKILL。卡片按钮与 `/stop` 命令两条停止路径同源受益。
- **进行中卡片重新看得到上下文用量**。此前 `agentCardStream` 只在 Start 时读一次 sidecar 快照，`Handle` 期间从不刷新；首轮新会话 SessionID 为空时 `contextusage.Read` 直接返回空 Usage。现在 Handle 每帧 `refreshContextUsageLocked`：只要本轮已知 SessionID 就 `ReadAfter(runStartedAt)` 拿本轮 fresh 值升级 meta 并置 `CtxApprox=false`。首轮卡片 footer 也重新显示 Session ID 与 ctx。
- **Bash 等工具输出过长时卡片不再只剩输出、看不到命令**。旧逻辑超容后从工具段头部截断，先丢掉工具名和命令围栏。现在单次工具输出最多保留 6000 字符，按约 60% 头部 / 40% 尾部保留并显式标记中间省略；工具名和命令始终完整展示。
- **`append-clean-card` 工具区不再重复展示 `Bash call_xxx` 与 raw JSON**。同一个 `tool_use.id` 收到多帧（占位 input → 完整 input）会被 append 成多行；改为按 id 归一的 (name, command, output) 三元组，同 id 覆盖不追加。命令/输出提取有三级兜底。
- **`append-clean-card` 思考区不再累积多轮 COT**。vendor 不发标准 `AssistantSnapshot` 时 `cleanThought` 会跨轮累积；每个非 incremental thought segment 首帧无条件 Reset，恒只保留最新一轮完整内容。
- **工具调用卡片流式布局竖排乱码**。Claude 流式输出里 tool_use 的 input 经 `input_json_delta` 分片到达，单片是未闭合 JSON 碎片，旧代码把碎片当 SegmentTool 逐片追加进过程区，飞书窄面板按字符硬折行。丢弃 `input_json_delta` 碎片（完整 input 仍由 content_block_start block + 终态 assistant message 呈现）；空 input 跳过围栏。
- **`/config` 元信息行的三个复选框勾了不生效**（rc.7 引入、rc.10 修复）。飞书 CardKit 的 `checker` 组件视觉是复选框但**不是 form 输入字段**，勾选状态不会被 form.submit 收集。回退到 `select_static` 两选项下拉（「隐藏」/「显示 XXX」）。
- **`/config` 下拉宽度参差不齐**。飞书 `select_static` 默认按内容宽度呈现；给两个 select 工厂统一加 `"width": "fill"`，卡片内所有 select 都占满卡片全宽。
- **话题群 session 频繁切换 / 丢失上下文**。rc.7 引入的 per-mention 合成 session key 别名只在内存，supervisor 重启后丢；改为持久化 `TopicAliasStore` + `root_id` 自愈兜底路由；`RecordCardReply` 的 alias 源修正为真实合成 thread。
- **话题首条非 @ 消息被 `topic_not_participated` 丢弃**。用户 reply mode 是"话题内都回复"时，bot 用 `reply_in_thread=true` 回复后飞书分配的 `omt_*` 从没被 bridge 学习，下一条不 @bot 的话题内消息被 skip。新增 CardKit reply 成功时通过 observer 自动 `Mark` participation。
- **私聊用户白名单回复文案**改为明确区分「允许响应的用户」与群聊成员策略，避免把两类权限误认为同一作用域。
- **群聊与卡片操作访问控制加固**。拒绝卡片操作的重放、参数篡改、跨用户、跨会话、过期以及权限策略变更后的旧卡片操作，避免历史卡片绕过当前访问策略。

## Upgrade Notes

- 无需迁移。`/config` 元信息行 `show_meta_rows: true` 旧配置自动迁移为 agent+runtime 两行同开（不含 developer）。
- 新增 `topic-aliases.json`（默认 workspace 目录下）首次运行自动创建；缺失时靠 `root_id` 自愈路由，不影响既有会话。
- Supervisor 部署若只配了 stable manifest URL，启动会 stderr 打一条 warning；要接 rc 请补配 prerelease URL 并发 `/.devel 1`（参考 README 部署段与 self-loop 仓 `config/linux-supervisor.env.example`）。

## Miscellaneous

- `lark-bridge-release tag` 允许 release notes 省略无内容的 section，不强制 5 段全在。
- 发布链路 preflight：`publish.sh` 强制校验候选清洁度、`origin/main` ancestry、本地/远端 annotated tag；发布过程原子写 JSON 状态与独立日志（PID、phase、current artifact、时间、结果、退出码）。
- 发布验证与 release 命令隔离 supervisor 注入的运行时状态路径，避免默认配置测试误读生产状态。
