# v0.1.7-rc.9

## Breaking Changes

- 隐藏 self-loop 命令由 `/.todo` **改名**为 `/.go`。这是重命名而非新增别名：旧的 `/.todo` 不再识别，会返回 `unknown command`。仅管理员可用、不出现在 `/help`，用途不变（把参数作为「修复/改进 bridge 自身」的需求交给 agent 驱动 self-loop）。

## Features

- 无。

## Bug Fixes

- **停止按钮真正停得掉正在跑的 run**（rc.8 后合入、本 rc 首次进 prerelease 通道）。`CLIExecRunner.Run` 起 claude/codex CLI 时未设进程组，点停止只 SIGKILL 直接子进程（Node 壳），真正 streaming 的孙进程（bash 循环 / 工具 / sleep）被 init 收养继续跑、仍持 stdout 写端，导致 `parseClaudeStream` 的 `Scan()` 永久阻塞、`cmd.Wait()` 不返回、走不到停止终态。新增 `procgroup_unix.go`：`Setpgid=true` + `cmd.Cancel` 对整组发 SIGTERM + `WaitDelay=5s` 兜底 SIGKILL；`procgroup_other.go` 非 unix 空实现保可移植。卡片按钮与 `/stop` 两条停止路径同源受益。
- **引用消息的正文注入 agent prompt**（rc.8 后合入、本 rc 首次进 prerelease 通道）。引用/回复某条消息再 @bot 时，飞书入站事件只带被引用消息的 `parent_id`（不含正文），且该 id 在 `feishu.Event→bridge.Message` 映射时被丢弃，导致 AI 看不到被引用内容。修复：`bridge.Message` 透传 `ParentID`；新增 `MessageFetcher` seam 按 parent_id 回查正文；`session.Input` 加 `QuotedText`/`QuotedSender`；`BuildBatchPrompt` 把「> 引用块」渲染在用户提问前。回查失败降级为 audit `quoted_message_fetch_failed`，单条纯文本无引用保持旧 fast-path。
