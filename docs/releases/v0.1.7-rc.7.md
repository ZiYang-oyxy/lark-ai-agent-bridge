# v0.1.7-rc.7

## Breaking Changes

- 无。

## Features

- topic 会话模式下，群里每次顶层 @bot 都立即起一个独立会话并发跑，不再排队等前一条完成。Feishu 顶层 @bot 消息 `thread_id=""`，之前 `sessionKeyForMode` 会退化为 `{Agent, ChatID, Thread:""}` 与 chat root 同 key，同 chat 所有 @bot 落同一 session、被 `FreezeReadyBatch` 严格 FIFO 串行。新路由：`IsGroup && Mentioned && ThreadID==""` 时 mint 合成 thread key `@bot:<msg_id>`（常量 `SyntheticTopicThreadPrefix`），每条 @bot 独立 session、独立 batch、并发跑。保留并扩展了 97f9135 的 fork-session 机制：`forkSeedForTopicSession` 判据从 `msg.ThreadID != ""` 泛化为 `topicKey.Thread != "" && topicKey != rootKey`，合成 session 首轮仍走 `--resume <root> --fork-session` 从 chat root 的 Claude AgentSessionID 继承上下文。新增 `TopicAliasStore`：`TopicJoinObserver.RecordCardReply` 在 CardKit reply 拿到真 Feishu `thread_id` 时把它 Bind 回合成 key；话题内后续消息（带真 thread_id）通过 alias 路由回同一 pending session，续话连贯。`Service.keyForMessage` 助手统一 6 处 sessionKey callsite（intake / command / status / workspace / update），命令与对话都走同一别名解析。

## Upgrade Notes

- 无需迁移。合成 key 只在运行期存在，durable session store 依然按真实 (agent, chat, thread) 索引；chat 模式行为不变，现有 topic 内带真 thread_id 的消息路由不受影响。
