## Bug Fixes

- **修复"点停止卡很久"的极端场景**。真实观察到用户点停止后卡片 111 秒才进入「⏹ 已停止」终态,期间 stream 完全静默。根因:`parseClaudeStream` 阻塞在 `pipe.Read`,`cmd.Wait` 尚未启动,导致 `cmd.WaitDelay` 的 SIGKILL 兜底升级永远进不来——若 Node wrapper 起的 grandchild 通过 `setsid` 逃出 pgroup 且仍持有 stdout writer,scanner 就永远读不到 EOF。修复在 `Runner.Run` 里增加兜底 goroutine:`ctx.Done + stopGracePeriod` 到期主动 `pipe.Close()`,scanner 立即 EOF 返回,`cmd.Wait` 才能进入并让 WaitDelay 强杀。正常路径 Wait 已经关 pipe,这次 Close 幂等无副作用。L1 覆盖 `TestCLIExecRunnerStopUnblocksWhenChildIgnoresSIGTERM`(setsid 复现 grandchild 逃逸,不带修复 40s timeout FAIL、带修复 5.31s 通过);L3 真飞书 Test 群 /stop 至终态卡 0.84 秒。
