# v0.1.8-rc.1

## Breaking Changes

- 无。仅 `append-clean-card` 一个 reply mode 的卡片版式改动，不改 store schema、不改配置项。

## Features

- **`append-clean-card` 回复模式改用三段布局**，视觉对齐 `feishu-ai-agent-platform` 参考风格。运行 / 终态卡片由原本的单个「过程」合并折叠区，拆成有序的三段：
  - **① 💭 思考推理**（折叠区，正文之前，运行期默认展开、终态折叠）——只显示最新一轮 COT；标题带累计轮次「× N」，如「💭 思考推理（已完成 · ×2，点击展开）」。
  - **② 正文**——继续以原有节流方式流式输出。
  - **③ 🔧 工具调用**（折叠区，正文之后，默认折叠）——只显示最新一次工具调用的**命令 + 输出**，人读格式（`**Bash**` + 命令围栏 + `**输出**:` + 输出围栏），不再出现 `call_xxx` 内部 id 和 raw JSON。标题带累计次数「× N」（按 `tool_use.id` 去重）。
- **终态卡片隐藏「已完成」灰按钮**。`append-clean-card` 终态视觉靠头部 `✅ 已完成 · ⏱ Xs` 已足够，之前那个占位灰按钮反而打断节奏。运行期红色可点击停止按钮保留。
- 其他回复模式（`append` / `latest-card`）行为不变，本次仅动 `append-clean-card` 的分支。

## Bug Fixes

- **`append-clean-card` 工具区不再重复展示 `Bash call_xxx` 与 raw JSON**。之前同一个 `tool_use.id` 收到多帧（占位 input → 完整 input）会被 append 成多行；改为按 id 归一的 (name, command, output) 三元组，同 id 覆盖不追加。命令 / 输出提取有三级兜底：`ToolMeta.Summary` → 从 raw text 的 ```json 围栏 parse `command` / `file_path` / `query` / `url` → 围栏原文。
- **`append-clean-card` 思考区不再累积多轮 COT**。之前当 vendor 不发标准 `AssistantSnapshot` 时，`cleanThought` 会跨轮累积；新规则让每个非 incremental thought segment（即 `content_block_start` 首帧）无条件 Reset，`sawTool` 兜底关轮触发下一段 Reset，恒只保留最新一轮完整内容。

## Upgrade Notes

- 无 breaking：默认 reply mode 不是 `append-clean-card`；只有已经切到该模式的 chat/global preference 会看到新版式。
- 无 store schema 变更，无环境变量 / 配置项新增，直接升级即可。

## Miscellaneous

- 实现要点：
  - `card.Event` 新增 `ThreeSectionLayout` / `ThoughtRoundCount` / `ToolRoundCount` 字段；`buildThreeSectionElements` 用 `collapsible_panel`（card schema 2.0）按顺序输出思考 panel → answer markdown → 工具 panel，展开态由 `ThoughtExpanded` / `ToolsExpanded` 决定。
  - `agentCardStream` 增设 `cleanThought` + `(latestToolID, latestToolName, latestToolCmd, latestToolOutput)` 三元组维护「只最新一次」。终态 `finalizeCleanSectionsLocked` 优先从 `result.OrderedSegments`（保留 `Tool` meta）提取工具三元组；普通 `result.Segments` 里 SegmentTool 是合并后的整段 markdown 文本、meta 已丢，只作兜底源。
  - `reply.cleanTerminalEvent` 在 `ThreeSectionLayout=true` 时保留 thought / tool segments（原「终态只留正文」的语义退给 latest-card 等旧分支）。
- **Trade-off**：动态思考区放在正文前会打破 native element-update 快路径的「正文是唯一 markdown」前提，`append-clean-card` 现在退回整卡刷新（与 `feishu-ai-agent-platform` 参考实现一致）。真机流式仍顺畅——CardKit `streaming_config` 保住卡内打字机观感。其他 reply 模式的 native 增量路径不受影响。
- L1：`go test ./...` 全绿（26 包），含新增的三段布局元素顺序 + × N 标题 + latest-only + 计数 + 终态保面板 + stop button 隐藏等单测。
- L2 & L3：`E2E_REPLY_MODE=append-clean-card` simulate 端到端产出三段结构；真机换血 Test 发消息，reply 卡片顺序、展开态、× N、人读工具格式、终态无 stop 按钮均已确认。
