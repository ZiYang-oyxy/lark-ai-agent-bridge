## Bug Fixes

- 修复 topic 会话模式群聊「同一话题内会话反复切换/丢失上下文」。rc.7 引入的 per-mention 合成 session key `@bot:<msg_id>` 只把真 Feishu `thread_id` 绑在内存，supervisor 重启/升级后绑定全丢，已有话题里的后续消息落到全新空会话。两处修复：
  - **持久化 `TopicAliasStore`**：按 `participation.Store` 模式重写（原子 temp-file + rename、schema version、revision、有界淘汰、开机加载），别名跨重启存活；经 `config.TopicAliasStorePath`（默认 `topic-aliases.json`，`E2E_TOPIC_ALIAS_STORE` 可覆盖）与 `OpenTopicAliasStore` 接入 main，`NewTopicAliasStore` 保持纯内存供测试使用。
  - **root_id 自愈**：Feishu 话题内消息带 `root_id`，而话题 root 恰是那条 seed 出合成 key 的原始 @bot 消息。`sessionKeyForModeWithAlias` 在别名 miss 时把真 thread 消息路由到 `@bot:<root_id>`，别名映射丢失也能续上。`Message` 新增 `RootID`（映射自 `InboundMessage.RootID`）。
  - 附带修掉 L3 暴露的 bind bug：`RecordCardReply` 之前从 `replyToMessageID` 取别名，话题内后续消息的 reply 目标是它自己而非 root，会把别名污染成 `@bot:<follow-up>`。现改为把本轮真实合成 thread（session key 的 Thread）经 `RenderBinding.TopicThreadKey` 传进 `RecordCardReply`，且仅在带 `@bot:` 前缀时才 bind，使 alias-hit 与 root_id-fallback 恒算出同一 key。
